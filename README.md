# MoriMori-App

技術書の「読書実験」アプリ。

## 解決したい課題

技術書を買っても、日常的に開かない。続かない。

- 買った直後はモチベーションがあるが、数日で開かなくなる
- 「読まなきゃ」という義務感がむしろ本を遠ざける
- 積読が増えるほど罪悪感が積み重なり、さらに開けなくなる悪循環

## コンセプト

読書を「習慣化」ではなく「実験」にする。

AIが科学的・理論的な根拠をもとに「この2冊を交互に読むと、片方だけでは見えない概念が繋がる」といった組み合わせ・読み順を提案する。ユーザーは実際に読んでみて、AIの理論が正しかったかを自分の実感で検証する。

例：「Swift Concurrency本」と「Erlangのアクターモデル本」を交互に読むと、actorの設計思想が2つの言語の対比で立体的に理解できる——とAIが根拠付きで提案。本当にそうだったかは、読んだ自分だけが知っている。

## なぜ開くのか

- 「読みたいけど開かない」のは義務感があるから
- 実験には仮説がある。仮説があると「確かめたい」が生まれる
- 「確かめたい」は義務じゃなく好奇心

## 主な機能

- 読みたい技術書を登録する
- AIが理論的根拠付きで読み合わせ（ペアリング）を提案する
- 実際に読んで、AIの予測と自分の実感のギャップを記録する
- ギャップの蓄積からAIの得意・不得意が可視化される

## 技術スタック

- Swift 6 / SwiftUI
- Swift Concurrency（async/await, actor）
- Claude API

## アーキテクチャ方針

副作用の隔離を徹底する。

```
Pure層:   ペアリングスコア計算、予測 vs 実績の分析、読書進捗の状態遷移
Effect層: Claude API呼び出し、DB永続化（SwiftData）、書籍情報API
Boundary: actor で Effect層をラップ。Pure層は struct + enum のみ
```
