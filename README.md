# MoriMori-App

技術書の「読書実験」アプリ。

## 解決したい課題

技術書を買っても、日常的に開かない。続かない。

- 「この本を読めばこれが理解できる」「こうなれる」というビジョンに感動して本を買う
- でもその感動は日々薄れていく。数日後にはもう開かなくなる
- 「読まなきゃ」という義務感がむしろ本を遠ざける
- 積読が増えるほど罪悪感が積み重なり、さらに開けなくなる悪循環

## 解決方法

薄れていく感動をAIが支え、好奇心を途切れさせない。

1. **ビジョンを思い出させる** — 「この本を読めばこうなれる」という最初の感動が薄れる前に、通知でビジョンを呼び戻す
2. **本を開く前に「確かめたい」を作る** — AIが「次の章では○○が出てくるけど、前にB本で読んだ△△と矛盾するはず」のような仮説を投げかける。問いがあるから確かめたくて開く
3. **読書をAIがサポートする** — 次のページで何が学べるかを伝え、読み進める後押しをする
4. **進捗を可視化する** — ゲージやパーセントで読書の進みが見える。積み上がっていく実感が続ける力になる
5. **AIが2冊の繋がりを見つける** — 反応が溜まると、自分では気づかなかった本同士の繋がりをAIが提示する。実験が勝手に育つ

## 主な機能

- 読みたい技術書を登録する
- AIが理論的根拠付きで読み合わせ（ペアリング）を提案する
- 実際に読んで、AIの予測と自分の実感のギャップを記録する
- ギャップの蓄積からAIの得意・不得意が可視化される

## 技術スタック

- Swift 6 / SwiftUI
- Swift Concurrency（async/await, actor）
- Claude API

## アーキテクチャ方針

副作用の隔離を徹底する。

```
Pure層:   ペアリングスコア計算、予測 vs 実績の分析、読書進捗の状態遷移
Effect層: Claude API呼び出し、DB永続化（SwiftData）、書籍情報API
Boundary: actor で Effect層をラップ。Pure層は struct + enum のみ
```
