# MoriMori-App

自己学習のための「読書実験」アプリ。

## 解決したい課題

学習のために本を買っても、日常的に開かない。続かない。

- 「この本を読めばこれが理解できる」「こうなれる」というビジョンに感動して本を買う
- でもその感動は日々薄れていく。数日後にはもう開かなくなる
- 「読まなきゃ」という義務感がむしろ本を遠ざける
- 積読が増えるほど罪悪感が積み重なり、さらに開けなくなる悪循環

## 解決方法

薄れていく感動をAIが支え、好奇心を途切れさせない。

1. **ビジョンを思い出させる** — 「この本を読めばこうなれる」という最初の感動が薄れる前に、通知でビジョンを呼び戻す
2. **本を開く前に「確かめたい」を作る** — AIが「次の章では○○が出てくるけど、前にB本で読んだ△△と矛盾するはず」のような仮説を投げかける。問いがあるから確かめたくて開く
3. **読書をAIがサポートする** — 次のページで何が学べるかを伝え、読み進める後押しをする
4. **進捗を可視化する** — ゲージやパーセントで読書の進みが見える。積み上がっていく実感が続ける力になる
5. **AIが2冊の繋がりを見つける** — 反応が溜まると、自分では気づかなかった本同士の繋がりをAIが提示する。実験が勝手に育つ

## ユースケース

### 始める

1. ユーザーが基本情報を入力する — 今の自分（職業・スキル・経験）、どうなりたいか、なぜ学習したいか
2. AIが基本情報をもとに興味のあるジャンル・分野の候補を提案する
3. ユーザーが興味のあるジャンル・分野を選ぶ
4. AIが選ばれたジャンルから読むべき本を根拠付きで提案する（「この本を読めばこうなれる」というビジョン付き）
5. ユーザーが本を選び、ビジョンを確認して読書を始める

### 日常（本を開かせる）

6. ビジョンが薄れる前に通知で思い出させる — 「この本を読めば○○が理解できるんでしたよね」
7. AIが次の章について仮説を投げかける — 「次の章で出てくる○○、前にB本で読んだ△△と矛盾するはず。確かめてみて」
8. AIが次のページで何が学べるかを伝える
9. 本を順番通りに読み進める
10. 進捗がゲージ・パーセントで更新される

### 実験が育つ

11. AIがペアリング（2冊の組み合わせ）を根拠付きで提案する
12. 読み進めるうちにAIが2冊の繋がりを見つけて提示する
13. AIの予測が合ってたか/違ったかを記録する
14. 蓄積をもとにAIの提案や通知の精度が上がる（ペアリング、仮説、モチベーションを上げるメッセージなど）

## 技術スタック

- Swift 6 / SwiftUI
- Swift Concurrency（async/await, actor）
- Claude API

## アーキテクチャ方針

副作用の隔離を徹底する。

```
Pure層:   ペアリングスコア計算、予測 vs 実績の分析、読書進捗の状態遷移
Effect層: Claude API呼び出し、DB永続化（SwiftData）、書籍情報API
Boundary: actor で Effect層をラップ。Pure層は struct + enum のみ
```
